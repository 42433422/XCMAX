- 模型多框了一段没有主单元格的空白范围时，这段不留成单据，其余有内容的范围和 can_slice 照常采用。只有空白、或范围互相重叠，整批仍拒绝。
- 类型识别如果把结果包在 output_schema 里面，会先取出里面的单据再校验，不再因为多包了一层就整批拒绝。
- 送货单表头写成「产 品 名 称」「数量/件」这类带空格或单位的样子时，仍按明细读取。表上没有客户名称时，用这一张表的名字作为购买单位。金额格是公式时用已经算出的数字，没有结果就不把公式原文写进去。
- 出货明细里校验不通过的行不写入业务库，仍留在知识库文档中；校验通过的行按预演写入。
- 模型把隐藏工作表单独划成单据时，自动切片保留复核副本，其余可见单据继续提取。
- 类型识别会告诉模型：每个范围至少要有一个非空主单元格，合并格里没有值不算；不要框全空的尾部行；范围不能互相重叠，否则整批不要。
- 工作表分析如果已经发出但没有存下模型回复，超过十五分钟后可以继续这一份，不会把还在进行的调用再发一次。已经存下回复的仍不重发。
- 工作表命名要求模型按张数给每一张表起名，公式表和原料表也不能漏。模型少给名字时，会把缺名的表再问一次。
- 模板预览不再因为模型点到一个越界或受保护的格子就整单失败，这个格子会被丢掉，其余候选仍返回。模型输出因长度被截断时，日志记下 finish_reason，并把这一次预览的输出上限从 1400 提到 4096；其他失败仍记下真实原因，等待时间不延长。
- 模型清理方案只点到少量备注时，预览会补上其余非公式的单据实例格再落盘。整段无法解析时保留本地清理方案，不再整单失败。知识库模型失败或截断时仍用归档原文预演并写入一份文档。工作表命名在已有事件循环里改走独立线程；模型若只返回名称数组、不带工作表名，仍按原表顺序把名称和类型写回切片。
- 模板预览按模型切出的单据显示胶囊，一片一个，胶囊上有名称和类型，可以点开查看。标成未知的表由模型按内容起名并定类型，模板名用这个名字。数据库导入会扫完每一张表，每一行货品单独成一条，没有购买单位时用整本表头上的客户，借还台账和测算表默认不导入。
- 数据对接入库时，数据库导入允许模型一次写完约一百行明细，并要求只返回以 rows 开头的单个 JSON 对象，不要代码块和解释。模型没交出合法 JSON 时，日志留下正文的开头和结尾。
- 数据对接入库预演里，数据库导入和知识整理读整张归档原表时，模型最多等 180 秒，不再在 12 秒处中断。页面会等这两次都结束再显示结果。预览和优化的等待时间不变。
- 数据对接：送货单打印区域越过所选片段时，自动切片改用所选片段作为派生打印区域并继续，不再因此返回 400；模型边界只盖住一部分主体时保留已覆盖区域，未覆盖的留给人工确认，不再返回「可能已计费、不可重试」的 503，也不会自动再提交；整本分析的页面等待加长到能读完已返回的结果，其他接口超时不变，卡住的调用仍会停止。
- 数据对接里数据库导入员和知识整理员不再用白底方框回报，改成顺着模板胶囊往下说的一段对话：三个人各是一个节点，中间有一根细线连着，数量和文档内容直接写在话里。数量为 0 仍写 0；跳过或结果不可用时写明没有做完。
- 数据对接里要等模型的分析、预览、优化和入库预演，以及这段时间里的桌面会话探测，不再按 8 秒判失败。页面会等到模型做完再报结果；短调用仍很快停下，整表导入每条最多 180 秒。请求真卡住仍会停。
- 数据对接在模板胶囊旁边列出数据库导入员和知识整理员的工作情况：上面是员工，中间是这一次的结果，下面是客户、购买单位、产品、明细或文档数量。数量为 0 就写 0；跳过或结果不可用时写明没有做完，表头文字不会被写成客户。
- 模板库、数据库导入和知识库各自调用一次模型，一次失败不会关掉另外两条。数据库导入和知识库都读归档原表；知识库没有可用模型结果时不写入，数据库导入仍按原单明细入库，表头不会进业务记录。
- 送货单确认入库后，按原单上的客户和明细写入发货记录；表头文字不会被当成客户或购买单位。

- 批量对话在前序任务等待授权、补参或结果未确认时暂停后续项，并保留每项编号和回执；聊天与员工共用结果状态规则，等待中的原任务可以继续写回最终结果。

- 表格结构识别不再因客户名以“说明/备注”开头或地址过长而排除合法业务行；疑似内容保留给后续校验，明确备注标签仍单独处理。
