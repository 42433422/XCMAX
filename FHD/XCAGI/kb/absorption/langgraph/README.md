# LangGraph 吸收分析（Retort 引擎）— 结论速览

> 生成时间：2026-08-06（UTC）
> 用途：面向非技术读者的简明结论。技术细节见同目录 `absorption_evidence.json`（吸收证据）与 `absorption_tasks.json`（待吸收任务清单）。

## 一句话结论

我们用 Retort 引擎对 **LangGraph**（领先的『有状态智能体工作流』框架）与 **FHD/XCAGI** 的 NeuroBus 做了一次"吸收深度"分析。结论是：**FHD 的 NeuroBus 是一套很可靠的"事件总线 + 处理器"，但缺少 LangGraph 那层"有类型的图状态 + 可路由 / 可续跑 / 可回放"的编排原语**，值得吸收。

## FHD 现状（NeuroBus）

- 已经通电：事件总线、8 大可靠性机制（去重/熔断/限流/保命/追踪/死信/SLA/重试）、意图反射弧、处理器协调器。
- 缺口：处理器是**线性/优先级链**，事件载荷是**无类型字典**，没有**断点续跑**、**时间旅行回放**、**流式状态事件**、**人工中断/恢复**、**子图组合**。

## LangGraph 提供了什么（值得吸收）

| 能力 | 通俗解释 | 吸收优先级 |
|------|---------|-----------|
| 有类型状态 + 合并规则 | 状态是"有结构的表格"，并发写按规则合并而非覆盖 | P0 |
| 条件路由 | "下一步做哪步"由当前状态决定，可测试可扩展 | P0 |
| 断点续跑 | 长流程崩溃后从最近一步继续，不重头来 | P0 |
| 并行扇出 | 一次任务并行派发多个子任务，完成后汇总 | P1 |
| 时间旅行 | 回退到历史某步、修正后重跑（调试神器） | P1 |
| 流式状态事件 | 前端一步步看到执行进度 | P1 |
| 人工中断/恢复 | AI 流程执行到审批点挂起，人工确认后继续 | P1 |
| 子图组合 | 领域流程打包成可复用、可独立验证的模块 | P2 |
