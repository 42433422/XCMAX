# Default-on memory, offline semantic migration and bounded automatic review

- Neuro working memory defaults to short + governed long-term recall. Explicit opt-out remains supported.
- Embedding defaults to auto: verified, locally provisioned FastEmbed is preferred, otherwise hash. The chosen vector space and fingerprint are fixed per process. The release model manifest includes its bytes' digest and probed dimension. Provisioning happens in the build; frozen desktop and server release bootstrap require an offline probe, not a runtime download. The pinned FastEmbed runtime manifest reuses the version already recorded in the existing lock.
- Existing 256-dimensional user/employee Hash records remain the source for the rebuildable semantic projection. The new cache is keyed by source chunk and model fingerprint, checks the original content hash and dimension, and is removed with its source chunk. Lazy migration covers the bounded live index on each query; an unavailable model or failed migration falls back to the complete legacy Hash query rather than combining incompatible scores. MemoryV2 and employee provenance validation still gate results. No remote user-text embedding is introduced by migration.
- MemoryV2 remains authoritative. Persy capture defaults to automatic review of independently matched, single direct low-risk assertions. Private preferences/habits, explicitly scoped global preferences, and authorized tenant business assertions in a narrow predicate allowlist qualify. No implicit tenant or global publication; source and access checks are unchanged.
- Historical pending candidates are reviewed in batches of five during authorized chat captures. The scoped POST /datasets/{dataset_id}/memories/auto-review endpoint accepts scope, limit (1–100) and after cursor. Both paths re-read the authenticated user's stored message and check the server-bound conversation key, scope, tenant, Mod, original excerpt, candidate revision, conflicts and deletion/supersession fences. Eligible existing records retain their memory ID and advance revision with an auditable receipt; missing or ambiguous evidence stays pending. Older history that cannot be independently verified is not bulk-approved.
- Set XCAGI_MEMORY_AUTO_REVIEW=0 to disable automatic review; XCAGI_MEMORY_CAPTURE=0 stops automatic capture. Existing records, deletion tombstones, revision validation and projection repair remain intact.
- Release acceptance requires CI, real installed-model fingerprints, SQLite/PostgreSQL migration and rollback, tenant/Mod isolation, and desktop/production performance verification. This change alone does not certify runtime readiness.
