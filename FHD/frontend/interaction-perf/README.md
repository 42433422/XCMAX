# Interaction performance evidence / PR #3605

Baseline: `b0f9b3ba9ad4d856248fe7c792a43e99e0b12f03` (pre-performance changes, includes parallel frontend work). The dedicated workflow builds that revision and the exact candidate head with the same test fixture, Chromium version, runner, viewport and Node version. A clean production preview is launched per side.

- Route: shell readiness (runner wall time), first settings switch and history back recorded separately; 30 warmed round trips use the renderer clock and two ready animation frames. The 200 ms P95 target is reported, not a claim of passing. Request counts by endpoint are diagnostic, not proof that all requests are redundant.
- SSE: a timed synthetic ReadableStream feeds 242 tokens into the existing POST chat stream and parser. The visible DOM must receive the initial token before the terminal event and eventually render the final marker. Fixture delivery wait, first-token-to-visible-frame delay, input-to-request time and raw rAF intervals are separate. These intervals are a presentation cadence proxy, not GPU raster time. Network and model inference are intentionally null. No external account or model is used.
- Results: each side writes raw JSON, source SHA, runner details and logs. Failed or missing samples are not replaced with estimated values. Candidate and baseline run sequentially; shared-host noise and order effects remain limitations.
- This is a production **web renderer** benchmark with a synthetic desktop bridge, not native Electron, Windows/macOS, Android/iOS or a customer acceptance result. Native profile/device measurements are still BLOCKED until a real target and SDK are available.
- Run locally after `npm ci` and `npx playwright install chromium`: set `SOURCE_SHA` to the actual checkout SHA, build with `VITE_XCAGI_GIT_SHA="$SOURCE_SHA" VITE_CHAT_STREAM=1 VITE_CHAT_STREAM_PATH=/api/ai/chat/stream npm run build`, then run `npx playwright test --config playwright.interaction-perf.config.ts`.
- No production behavior changes in this baseline commit. Do not infer improvements before both measured runs succeed. The baseline SHA for PR #3605 remains fixed across subsequent commits. No second chat scheduler or virtual list is introduced.
