# 微信同步代理与 AI 刷新

此目录是 Windows 本地微信数据库采集代理的源码。`wechat_sync.py --loop` 按配置周期同步，并每两秒检查服务器上的刷新请求。只运行一次的模式不领取后台刷新请求。

使用原有 `wechat_sync_config.json` 或环境变量配置服务器地址、ops token 和正整数 `tenant_id`。刷新与查询针对该租户；`contacts` 和 `limit` 继续决定采集范围，不代表获取全部历史聊天记录。不要将 token、数据库密钥或本机缓存加入版本控制。

服务端需先执行 Alembic 迁移至 `2026_09_08_wechat_refresh` 或后续版本。请求、租约与回执保存在宿主数据库 `wechat_refresh_requests`，与实际摄取的宿主微信数据使用同一租户范围。

- `refresh_contact_cache` 读取联系人并上行，不读取消息、不推进消息游标。
- `refresh_messages_cache` 采集配置范围内的最近消息，上行成功后才推进游标。
- 前台直接调用等待回执最多 10 秒，未完成时返回状态和 `request_id`，可用 `wechat.query` 查询。已批准的后台任务在请求有效期内继续等待回执，由原执行器更新原任务结果，只执行一次正常计费流程；等待会占用一个后台执行槽位，最多 15 分钟。重试同次刷新需复用 `request_key`；后台任务默认使用持久任务幂等键。
- 后台等待读取持久暂停/取消指令。暂停阻止尚未领取或租约过期的请求再次被领取；恢复复用原步骤审批和请求。已开始的本机采集不能远程强制停止，但取消会拒绝其后续回执，不会宣称已经撤销采集。中断不会作为业务失败训练样本记录；中断调用退款，恢复完成后净计费一次。
- 请求有效期为 15 分钟，领取租约为 5 分钟；过期后不能提交完成结果。采集端断线重连可重新领取未过期请求。过期租约回执、其他租户回执和相互矛盾的重复回执均拒绝。
- ops token 仅用于采集端领取和回执，不通过 AI 参数传递。AI 查询和请求使用宿主验证的账号与租户；刷新状态只对请求账号可见。

联系人数据库读取失败或消息采集失败会返回失败，不能作为“没有新数据”处理。本地链路测试使用真实 HTTP 路由和 SQLite，替换 Windows 数据库读取边界；Windows 实机采集、长耗时采集与已安装交付仍需要单独验收。
