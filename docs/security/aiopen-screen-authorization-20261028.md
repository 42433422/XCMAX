# AIOPEN 屏幕目标授权候选修复 — 2026-10-28

## 权限契约

屏幕凭据必须由服务端绑定明确的 principal_id 和 tenant_id。管理端生成运行时 Key 时仅从 require_admin_user 的认证结果建立绑定，忽略正文中的用户和租户字段。旧 Key 和环境变量 Key 继续服从现有非屏幕工具鉴权，但不因此获得任何屏幕所有权；存在 Key 请求头时不会借用另一浏览器登录会话提升该 Key 权限。

最终 CursorHub 对屏幕枚举、默认目标、显式目标和命令历史统一检查同一用户且同一租户。未绑定身份默认拒绝，未知与外部目标返回同样的拒绝响应，不枚举其他屏幕。ContextVar 通过 async dependency 的 try/finally 限定到请求；既有 asyncio.to_thread 路径继承同一上下文。

## 迁移影响（不能跳过）

需要屏幕操作的客户端必须由具有真实用户 ID 和 tenant_id 的已认证管理员重新签发运行时 Key，并使用同一身份的屏幕会话。缺失 tenant_id 时不自动假定租户 1 或构造共享租户。原来使用全局环境 Key、未绑定旧 Key 或控制其他账号屏幕的方式将被拒绝。跨用户委托不是本次支持的策略；所有者限定是有意的安全收紧。真实单机/企业账号模型、前端错误提示和升级流程尚须端侧兼容验收，故保留草稿。
